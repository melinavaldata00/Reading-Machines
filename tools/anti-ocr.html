how anti type works

For each letter, the hosted Python server renders it as a glyph image and then loops: apply a Fourier-transform frequency filter that erodes fine detail from the shape, then ask Tesseract OCR to try reading that single letter back. As long as Tesseract can still recognise it above the confidence threshold, the loop keeps going and the degradation gets a little heavier each pass. The moment OCR's confidence drops below the threshold, the server remembers the last iteration where it could still read it — that's the "blind point" — and that's the version of the glyph you get back, not the fully-degraded one.

So every letter is only as broken as it needs to be to stop being machine-legible, which is why some letters shift more than others even at the same settings — it depends on how quickly Tesseract loses confidence in that particular shape.

parameters

iterationshow many degradation passes to try, at most
blind thresholdOCR confidence (%) below which a letter counts as unreadable
frequency intensityhow much of the image's frequency detail gets cut per pass
glyph sizepixel size of the rendered glyph sent to the server for each pass

This all runs on a free hosting tier with a shared, throttled CPU — each Tesseract call has real, unavoidable cost, which is why longer words and full-alphabet font export take a while, and why they're processed one letter at a time rather than in parallel (that was tried — it made things slower, not faster, on this kind of shared CPU).
