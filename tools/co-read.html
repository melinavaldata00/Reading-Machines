how reading loop works

Unlike the other tools, OCR here runs entirely in your browser via Tesseract.js — no server involved. The image is first cleaned up (grayscale, contrast stretch, adaptive local-threshold binarization) to help Tesseract separate text from busy or coloured backgrounds, then read. Each recognised word becomes an editable shape: its position and text come from Tesseract, and how "broken up" it looks is driven by two things — the OCR confidence for that word, and how visually complex the word's own pixels are (edge density and size). Low confidence or high complexity means a sparser, more scattered pattern.

What you see is two layers per word: a soft, low-opacity fill (a halftone-style "silhouette" of the ink), and a sparser dotted texture on top tracing just the edges — together they're what makes the shape still read as a letterform rather than random noise.

re-read is the actual "loop": it renders the current state back to an image and feeds that back into Tesseract, so the machine reads its own already-abstracted output — confidence usually drops a bit each time, which is blended with the previous reading so words don't flicker unpredictably between passes.

Alongside OCR, the same read pass also runs OpenCV in the browser to trace marks, drawings, or symbols Tesseract didn't recognise as words — anything left over once the text is accounted for. Each one becomes its own editable outline shape (contour + light fill by default), positioned exactly where it was traced in the source image, and driven by the same drag / color / opacity / rotation / skew / scale / disperse controls as every word.
